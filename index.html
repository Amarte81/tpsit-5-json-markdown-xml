🌐 A cosa servono i Linguaggi di Interscambio dei Dati?

FONDAMENTI DI ARCHITETTURA DI RETE

Nelle moderne architetture distribuite, programmi scritti in linguaggi diversi e in esecuzione su sistemi operativi diversi devono scambiarsi informazioni continuamente. Pensa a una centralina domotica programmata in C che invia la temperatura a un server centrale scritto in Java, il quale a sua volta risponde a un'applicazione mobile o a un sito web in JavaScript.

Questi sistemi sono eterogenei: una struct in C, un oggetto in memoria RAM della Java Virtual Machine (JVM) e un oggetto del browser hanno rappresentazioni binarie incompatibili tra loro. Non è possibile inviare direttamente sulla rete un indirizzo di memoria RAM da un computer a un altro.

1. La Lingua Franca Testuale

I linguaggi di interscambio dei dati (come JSON e XML) risolvono questo problema fornendo un formato testuale standardizzato e neutrale. Qualsiasi linguaggio di programmazione sa leggere e scrivere stringhe di testo codificate in UTF-8.

2. Serializzazione e Parsing

Il mittente esegue la serializzazione: trasforma il proprio oggetto in memoria in una stringa strutturata da trasmettere in rete. Il destinatario esegue l'operazione inversa, chiamata deserializzazione (o parsing), ricostruendo i dati nelle proprie variabili.

3. Dati per Macchine vs Umani

Mentre JSON e XML strutturano dati destinati ai programmi, i linguaggi di markup leggero come Markdown strutturano il testo affinché sia immediatamente leggibile dagli esseri umani e facilmente elaborabile dalle Intelligenze Artificiali.

📖 Guida Teorica Modulo 1: Come funziona JSON e perché domina il Web

TEORIA AD ALTA DENSITÀ

JSON (acronimo di JavaScript Object Notation) è oggi il formato di interscambio dati più utilizzato al mondo per le API Web REST, le applicazioni mobile e i dispositivi IoT. Sebbene il suo nome derivi da JavaScript, JSON è totalmente indipendente dal linguaggio: viene generato e letto nativamente in Java, C, Python, C# e qualsiasi altro ambiente moderno.

Il successo di JSON nasce dalla sua compattezza e dalla corrispondenza diretta con le strutture dati che già usi quando programmi in Java. Ogni documento JSON si costruisce combinando solamente due strutture fondamentali:

  • L'Oggetto JSON { ... }: è delimitato da parentesi graffe e contiene una collezione di coppie "chiave": valore separate da virgola. Corrisponde esattamente a un'istanza di una classe Java (es. new Studente()), dove ogni chiave (sempre racchiusa tra doppi apici obbligatori) rappresenta il nome di un attributo e il valore ne rappresenta il contenuto.
  • L'Array JSON [ ... ]: è delimitato da parentesi quadre e contiene una lista ordinata di valori separati da virgola. Corrisponde a un array (String[]) o a una collezione (ArrayList<T>) in Java.

A differenza del semplice testo libero, JSON è tipizzato: distingue in modo netto le stringhe (tra doppi apici "testo"), i numeri interi o decimali (scritti senza apici e con il punto decimale, es. 42 o 24.5), i booleani (scritti rigorosamente in minuscolo true o false) e il valore nullo (null). Basta violare una sola di queste regole sintattiche per impedire al parser del destinatario di ricostruire l'oggetto in memoria.

☕ Integrazione Java: Come gestire JSON con Gson e Jackson

          JAVA OOP & SERIALIZZAZIONE
        

        

          In un'applicazione backend Java (es. Spring Boot o server Socket), il codice non manipola stringhe JSON grezze con operazioni di split. Si utilizzano librerie di Object Mapping come Google Gson o Jackson (ObjectMapper).
        

        

          Queste librerie trasformano automaticamente una classe Java (POJO) in stringa JSON tramite serializzazione (gson.toJson(oggetto)) e ricostruiscono l'oggetto Java tipizzato partendo da una stringa ricevuta via rete tramite deserializzazione (gson.fromJson(json, Classe.class)).
        

        
        
💻 Esempio Completo in Java (con libreria Gson / Jackson):

        
import com.google.gson.Gson;

// 1. Definizione della classe Java POJO (Plain Old Java Object)
class Sensore {
    private String id;
    private double temperatura;
    private boolean attivo;

    // Costruttore vuoto predefinito (indispensabile per i parser JSON)
    public Sensore() {}

    public Sensore(String id, double temperatura, boolean attivo) {
        this.id = id;
        this.temperatura = temperatura;
        this.attivo = attivo;
    }

    public String getId() { return id; }
    public double getTemperatura() { return temperatura; }
}

public class MainJsonJava {
    public static void main(String[] args) {
        Gson gson = new Gson();

        // SERIALIZZAZIONE: Da istanza Java a stringa JSON di rete
        Sensore s1 = new Sensore("ESP32_LAB", 24.5, true);
        String jsonPayload = gson.toJson(s1);
        System.out.println("JSON generato per l'API:\n" + jsonPayload);

        // DESERIALIZZAZIONE: Da stringa ricevuta a oggetto Java tipizzato
        String jsonRicevuto = "{\"id\":\"SENS_02\",\"temperatura\":19.8,\"attivo\":false}";
        Sensore s2 = gson.fromJson(jsonRicevuto, Sensore.class);
        System.out.println("Oggetto Java ricostruito: ID=" + s2.getId() + " Temp=" + s2.getTemperatura() + "°C");
    }
}

📖 Guida Teorica Modulo 2: Cos'è Markdown e perché ha sostituito Word nello sviluppo software

          TEORIA AD ALTA DENSITÀ
        


        

          Se JSON è perfetto per far comunicare due programmi, diventa invece scomodo quando dobbiamo scrivere una guida tecnica, un manuale di installazione o una risposta articolata da far leggere a una persona. D'altra parte, i formati di videoscrittura tradizionali (come i file .docx di Word) sono file binari complessi che non possono essere confrontati riga per riga nei sistemi di controllo versione come Git e richiedono programmi pesanti per essere aperti.
        


        

          Per risolvere questo problema è nato Markdown (file con estensione .md): un linguaggio di markup leggero che utilizza semplici caratteri di punteggiatura della tastiera (come #, *, -, `) per indicare titoli, grassetti, elenchi, tabelle e blocchi di codice sorgente.
        


        

          La forza di Markdown risiede in due caratteristiche tecniche decisive:
          1) Leggibilità immediata: un file .md è puro testo (plain text) chiarissimo da leggere anche dentro un semplice terminale o blocco note, ma viene automaticamente trasformato in una pagina HTML elegante quando viene visualizzato su GitHub, nelle chat di Discord/WhatsApp o nelle interfacce web;
          2) Standard per l'Intelligenza Artificiale: tutti i moderni Large Language Models (LLM) sono addestrati per ricevere istruzioni (prompt) e restituire codice e spiegazioni strutturate esattamente in Markdown, poiché consuma pochissimi token rispetto all'HTML o all'XML.

📖 Guida Teorica Modulo 3: Il Confronto con XML e i Criteri di Scelta Ingegneristica

          TEORIA AD ALTA DENSITÀ
        


        

          Prima dell'affermazione di JSON, lo standard universale per lo scambio di dati in rete era l'XML (eXtensible Markup Language). A differenza dell'HTML (che usa tag predefiniti come <p> o <h1> per impaginare una pagina web), XML permette al progettista di inventare i propri tag (es. <sensore id="1"><temperatura>24.5</temperatura></sensore>) per organizzare i dati in una rigorosa struttura ad albero.
        


        

          Perché allora nelle API moderne e nell'IoT si preferisce quasi sempre JSON rispetto a XML? Per due ragioni tecniche misurabili:
          1) La verbosità (overhead di rete): in XML ogni dato deve essere racchiuso tra un tag di apertura e uno di chiusura completo, raddoppiando spesso il numero di byte trasmessi sulla rete;
          2) Il costo di parsing: per leggere un documento XML in Java occorre caricare l'intero albero di nodi in memoria RAM tramite un parser DOM (Document Object Model) o scorrere gli eventi con un parser SAX, mentre un oggetto JSON viene mappato direttamente negli attributi di una classe Java con un'unica istruzione.
        


        

          Tuttavia, XML non è affatto scomparso. Un buon informatico sceglie XML quando il contesto richiede validazione formale rigorosa tramite schemi XSD (XML Schema Definition) o DTD, supporto per namespace multipli o attributi sui nodi: è il caso del file pom.xml che gestisce le dipendenze dei progetti Java Maven, dei file di layout delle app Android e dei protocolli istituzionali o bancari ad alta criticità.

☕ Integrazione Java: Parsing XML con DOM, SAX e JAXB

          JAVA XML PARSING
        

        

          In Java l'elaborazione di documenti XML è parte integrante del package standard javax.xml.parsers. Esistono due approcci di parsing architetturalmente distinti:
        

        
    
          
  • 
            Parser DOM (Document Object Model): carica l'intero albero XML nella memoria RAM della JVM (oggetti Document, Element, NodeList). È comodo per navigare e modificare nodi, ma consuma molta memoria RAM se il file supera alcuni megabyte.
          
    • 
          
  • 
            Parser SAX (Simple API for XML) o StAX: analizza il file in streaming sequenziale a eventi senza caricare l'albero in memoria. Ideale per flussi di dati enormi.
          
    • 
          
  • 
            JAXB (Java Architecture for XML Binding): converte automaticamente oggetti Java in XML (Marshalling) e viceversa (Unmarshalling) tramite annotazioni come @XmlRootElement.

💻 Esempio Completo in Java (Parsing DOM con DocumentBuilder):

        
import javax.xml.parsers.DocumentBuilderFactory;
import javax.xml.parsers.DocumentBuilder;
import org.w3c.dom.Document;
import java.io.ByteArrayInputStream;

public class EsempioXmlJava {
    public static void main(String[] args) throws Exception {
        String xml = "<config><porta>8080</porta><db>tpsit_db</db></config>";

        // 1. Inizializzazione della factory DOM standard di Java
        DocumentBuilderFactory factory = DocumentBuilderFactory.newInstance();
        DocumentBuilder builder = factory.newDocumentBuilder();

        // 2. Parsing della stringa XML in un albero DOM navigabile in RAM
        Document doc = builder.parse(new ByteArrayInputStream(xml.getBytes("UTF-8")));
        doc.getDocumentElement().normalize();

        // 3. Estrazione dei dati dai tag
        String porta = doc.getElementsByTagName("porta").item(0).getTextContent();
        String db = doc.getElementsByTagName("db").item(0).getTextContent();

        System.out.println("Configurazione letta da XML: Porta=" + porta + ", Database=" + db);
    }
}
